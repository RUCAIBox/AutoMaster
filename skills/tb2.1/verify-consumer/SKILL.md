---
name: verify-consumer
description: Check a changed deliverable through the interface and property its user will rely on.
---

When changing code, data, or a running service, connect the final check to the requested result:

1. Identify the user's actual entry point and one decisive property from the request or existing caller. Preserve that contract while solving the problem.
2. Exercise the finished deliverable. Reopen the saved file, load the exported model, rerun the original failing command, or perform the real service operation, as applicable. Use the required arguments, names, formats, and inputs. A check that adapts itself to your changed interface cannot establish compatibility.
3. If a report describes output quality or improvement, measure that property on the finished output. Compare input and output with the same definition and units. Compute the report from those observations; a planned transformation or intermediate value is not a measurement of the delivered result.
4. Follow a failed check back to its cause, repair it, and repeat the same check. Preserve a working version before speculative changes; restore it if a later experiment fails. Keep the final artifact and report consistent.

Once the requested result has been demonstrated, stop unless a concrete contradiction remains. Repeated readbacks and additional unsupported assumptions do not strengthen that evidence. State an unresolved limitation instead of certifying an unmeasured property.
